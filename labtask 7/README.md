# Lab Task 07 — Both parts

This solution extends the supplied Week 7 `01-memory-api.js` and uses its `02-persistent-api/store.js` queued, atomic JSON-file persistence pattern. Only built-in Node.js modules are required (Node 22 or newer). No npm install, database server or API keys are needed.

## Run

From this folder, run these in separate terminals:

```powershell
npm run student
# Part 1: http://localhost:3004
npm start
# Part 2: http://localhost:3005
npm test
```

Set the PORT environment variable to override the default. Part 1 starts empty and resets when stopped. Part 2 seeds the eight products and five categories from the Lab 3 Fitcheck catalog and saves changes to `data/shop.json`. Keep that file between runs. The original Fitcheck HTML remains a browser-local demo; this assignment supplies its backend endpoints, without changing the existing frontend.

## Endpoint reference

Each collection supports `GET /resource`, `GET /resource/:id`, `POST /resource`, `PUT /resource/:id`, `PATCH /resource/:id`, and `DELETE /resource/:id`. Orders support only list, read and create to preserve inventory and historical totals. An optional `/api` prefix also works. PUT replaces all editable fields; PATCH changes supplied fields. IDs are generated by the server and cannot be supplied or modified.

| Part | Resource | Required POST/PUT fields |
| --- | --- | --- |
| 1 | students | name, rollNumber, email |
| 1 | teachers | name, email, subject |
| 1 | attendance | studentId, teacherId, date (YYYY-MM-DD), status (present/absent/late/excused) |
| 1 | marks | studentId, teacherId, subject, exam, score, maxScore |
| 2 | categories | name |
| 2 | products | name, price (PKR), categoryId, stock (integer) |
| 2 | customers | name, email |
| 2 | carts | customerId, items (array of productId/quantity objects) |
| 2 | orders | customerId, items (nonempty), address |
| 2 | reviews | customerId, productId, rating (1–5), comment |

Send JSON with `Content-Type: application/json`. GET collections accept exact-match query filters for studentId, teacherId, customerId, productId, categoryId, status and date. Responses use 200 for reads/updates, 201 for creates, 204 for deletes, 400 for invalid data, 404 for missing records, 409 for duplicate/reference/stock conflicts, 413 for oversized payloads, 415 for incorrect content type and 405 for unsupported methods.

Students require unique roll numbers and emails; teachers/customers require unique emails. Attendance is unique per student, teacher and date. Foreign IDs must exist. Delete dependent records before deleting referenced records. Marks must be between zero and maxScore. One cart is allowed per customer. Item quantities must be positive integers and products cannot appear twice in an item list.

Order creation calculates totals using current server prices, snapshots product names/prices, deducts stock and clears the customer's cart in one queued file transaction. Failed orders do not change stock. The persistent store supports concurrent requests in a single server process; run only one shop process per data file. This is a classroom API with no real authentication, payment processing or card collection. Use fictional customer details.

## Try Part 1 (PowerShell)

```powershell
$student = @{name='Ali';rollNumber='241851';email='ali@example.com'} | ConvertTo-Json
Invoke-RestMethod http://localhost:3004/students -Method Post -ContentType application/json -Body $student
Invoke-RestMethod http://localhost:3004/students
Invoke-RestMethod http://localhost:3004/students/1 -Method Patch -ContentType application/json -Body '{"name":"Ali Khan"}'
Invoke-RestMethod http://localhost:3004/students/1 -Method Delete
```

Create a teacher before attendance or marks. For example, POST a teacher with `{"name":"Sara","email":"sara@example.com","subject":"CS301"}`, then attendance with `{"studentId":1,"teacherId":1,"date":"2026-10-25","status":"present"}` or marks with `{"studentId":1,"teacherId":1,"subject":"CS301","exam":"Lab 7","score":8,"maxScore":10}`.

## Try Part 2 (PowerShell)

```powershell
Invoke-RestMethod http://localhost:3005/products
Invoke-RestMethod http://localhost:3005/customers -Method Post -ContentType application/json -Body '{"name":"Ali","email":"ali@example.com"}'
Invoke-RestMethod http://localhost:3005/carts -Method Post -ContentType application/json -Body '{"customerId":1,"items":[{"productId":1,"quantity":2}]}'
Invoke-RestMethod http://localhost:3005/orders -Method Post -ContentType application/json -Body '{"customerId":1,"items":[{"productId":1,"quantity":2}],"address":"Demo campus"}'
Invoke-RestMethod http://localhost:3005/orders/1
# Stop/restart npm start, then GET /orders/1 again to confirm persistence.
```

Examples assume an empty database and IDs starting at 1. The automated tests use temporary files and ephemeral ports, leaving your saved data untouched. They cover both parts, CRUD, references, invalid input, duplicate attendance, stock conflicts under concurrent checkout, server-calculated prices, durable IDs, and persistence across server recreation.
